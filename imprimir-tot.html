Dossier docent de la formació — Servei Educatiu del Vallès Occidental II

Eines d'intel·ligència artificial per a l'aula

Amb el vibe coding no es guanya temps, però permet elevar els resultats

De la idea docent a la publicació d'un recurs web interactiu fent servir Google Antigravity i GitHub Pages, amb criteris de Vibe coding responsable i accessibilitat DUA.

Bloc 1

Marc: de la idea al recurs publicat

Com s'articula el flux de creació docent amb eines d'intel·ligència artificial

L'arribada dels assistents d'intel·ligència artificial permet als docents transformar indicacions pedagògiques en aplicacions web interactives autònomes (HTML, CSS i JavaScript) sense necessitat d'escriure codi a mà, seguint el paradigma del Vibe coding responsable.

1. El plantejament docent

La persona educadora defineix l'objectiu pedagògic i els criteris d'accessibilitat DUA.

2. L'agent de desenvolupament (Antigravity)

L'agent llegeix les indicacions pedagògiques i genera els arxius de l'aplicació directament a la carpeta de treball del disc dur.

3. Publicació i sobirania (GitHub Pages)

El projecte es publica com a pàgina web gratuïta, accessible des de qualsevol navegador sense registres ni anuncis.

Bloc 2

Google Antigravity: entorn de desenvolupament per a docents

Instal·lació, selecció de models Gemini i pautes d'indicació pedagògica

Google Antigravity s'executa com una aplicació nativa al vostre ordinador. Llegeix i escriu directament a la carpeta local que vosaltres decidiu (workspace), permetent crear aplicacions completes de manera transparent i segura.
  • Instal·lació al portàtil del PEDC: es pot instal·lar sense privilegis d'administració, atès que s'allotja al perfil d'usuari local.
  • Plan Review Policy (Revisió del pla): opció Always Review Plans per validar l'esquema pedagògic abans que l'agent toqui o creï fitxers.
  • Security Preset (Seguretat): mode segur amb autorització prèvia per a comandes i confinament estricte a la carpeta de treball (Workspace-only).
  • Models Gemini: models de la gamma Pro (amb raonament / Thinking si està disponible en el vostre compte) per estructurar activitats sense errors de sintaxi, i gamma Flash per a consultes curtes.
  • Les 4 pautes d'indicació: especificar nivell i àmbit concret, demanar fitxer autònom (index.html), exigir accessibilitat DUA i prioritzar retroacció pedagògica positiva.

Comparativa: Google Antigravity, OpenAI Codex i Claude Code d'Anthropic

Eina Interfície i entorn Punts forts pedagògics Adopció a l'aula
Google Antigravity Entorn gràfic integrat (IDE d'escriptori) amb previsualització en viu i panell d'agents. Diàleg en llenguatge natural i creació autònoma de projectes complets. Idoni per a docents: instal·lable al PEDC sense permisos d'administrador.
OpenAI Codex / Copilot Extensió d'autocompletat per a editors clàssics (Visual Studio Code). Molt veloç suggerint línies de codi i funcions mentre s'escriu manualment. Pensat per a perfils que ja programen; requereix subscripció o llicència educativa.
Claude Code (Anthropic) Línia d'ordres pura (terminal CLI a la consola del sistema). Raonament excel·lent en enginyeria de programari complexa amb Claude Sonnet. Barrera d'entrada alta per a docents no informàtics per manca d'interfície visual.
Bloc 3

GitHub i GitHub Desktop

Com desar les versions del recurs, sincronitzar-les i gestionar credencials

GitHub actua com un magatzem públic de repositoris que permet conservar l'historial de cada canvi (commits) i publicar la pàgina web gratuïtament amb el servei GitHub Pages. Per connectar-lo amb eines externes, es fa servir un Personal Access Token (PAT): github.com/settings/personal-access-tokens.

El repositori (repo)

És la carpeta del projecte. Perquè l'alumnat pugui accedir a l'activitat sense contrasenyes ni registres, ha de ser públic.

Commit i push

Desar una foto de seguretat dels canvis locals (commit) i pujar-la a GitHub (push) per actualitzar la web en directe.

GitHub Desktop al PEDC

Interfície visual senzilla per a Windows que s'instal·la al perfil d'usuari docent sense requerir permisos d'administrador.

Taula de credencials: tokens (classic) davant de Fine-grained tokens

Criteri Token (classic) Fine-grained token (beta) Què demanarà l'eina d'IA
Abast Tots els repositoris de l'usuari. Només els repositoris seleccionats. Antigravity prefereix Token (classic) per crear repositoris automàticament.
Configuració Molt senzilla: només marcar repo. Granular: configurar desenes de permisos manuals. El format clàssic evita errors de permisos permisos ocults.
Caducitat Sense caducitat o data lliure (tot el curs). Caduca obligatòriament (màxim 1 any). Si caduca a mig curs, l'eina no pot sincronitzar fins renovar-lo.
Recomanació Preferent per a docents. Útil per a comptes compartits o molt sensibles. Fórmula universalment compatible amb totes les eines Git.
Bloc 4

GitHub Pages en comparació amb Google Sites

Per què fer el pas cap a la publicació de codi propi amb assistència d'IA

Criteri GitHub Pages (amb suport d'IA) Google Sites (edició manual)
Creació i canvis Automatitzada per instruccions en llenguatge natural. Manual i feixuga, clic a clic.
Interactivitat pedagògica Completa: jocs de paraules, simuladors, retroacció didàctica immediata. Limitada a documents estàtics o formularis incrustats.
Sobirania i portabilitat Codi obert (HTML, CSS i JS) executable fins i tot fora de línia. Plataforma tancada, no exportable fora de Google.
Col·laboració docent Bifurcació senzilla (fork) per adaptar el recurs en segons. Gestió rígida de permisos per correu electrònic.
Bloc 5

Llicències: Creative Commons, codi obert i recomanacions per a docents

Com protegir i compartir adequadament continguts i codi

Un recurs web educatiu té dues dimensions: els continguts pedagògics (textos, activitats) i el codi informàtic (HTML, CSS i JS). Cal aplicar la llicència adequada a cadascuna mitjançant una declaració de doble llicència.

Taula de llicències recomanades per a docents

Tipus de recurs Llicència recomanada Què permet als companys docents Què cal evitar
Contingut didàctic CC BY-SA 4.0 (o CC BY 4.0) Descarregar i adaptar a l'aula, exigint compartir les millores en obert (REO). Evitar ND (impedeix el DUA i traduir) i NC (inseguretat jurídica en tallers i AFA).
Codi font web Llicència MIT (o GNU GPL v3) Clonar i executar lliurement a qualsevol ordinador d'aula o del PEDC. Evitar aplicar llicències Creative Commons al codi informàtic.
Icones ISC / MIT (Lucide, Tabler) Ús lliure en aplicacions sense restriccions ni costos. Evitar paquets privatius amb copyright tancat.
Imatges Llicències Unsplash / Pexels / CC Il·lustrar amb imatges reals d'alta qualitat citant amb patró TASL. Evitar imatges de Google sense filtrar drets.
Bloc 6

Recursos visuals: evitar l'excés d'IA, icones i citació d'imatges

Com construir materials rigorosos respectant l'autoria humana

Evitem generar imatges artificials per a finalitats purament decoratives: l'estètica hiperestilitzada de la IA pot restar credibilitat pedagògica. Prioritzem iconografia funcional (Lucide, Tabler) i fotografies reals de bancs gratuïts citades adequadament.

El patró TASL per a l'atribució a peu d'imatge:

Títol del recurs, Autoria (amb enllaç al creador), Source / Font (plataforma on s'allotja) i Llicència (amb enllaç a les condicions legals).

Bloc 7

Bones pràctiques: Vibe coding responsable a l'aula

Deu recomanacions essencials per a un ús responsable i de qualitat

  1. Revisar el contingut: fer l'activitat com a alumne abans de publicar-la; mai delegar el rigor a la IA.
  2. Protecció de dades: no introduir mai dades de l'alumnat; crear activitats que s'executin en local al navegador.
  3. Entendre el codi: demanar a l'agent que comenti i expliqui el funcionament de cada part.
  4. Autonomia: no dependre d'enllaços a servidors externs que puguin caure.
  5. Accessibilitat (DUA): contrast clar i bona navegació per teclat.
  6. Atribució: citar fonts, fotografies i fragments de codi amb el patró TASL.
  7. Traçabilitat: guardar les indicacions donades al fitxer README.md.
  8. Transparència: declarar al peu de la pàgina l'ús d'IA i la revisió humana docent.
  9. Llicència a la vista: indicar llicència oberta (com CC BY-SA 4.0) per garantir seguretat jurídica.
  10. Compartir el codi: enllaçar el repositori públic perquè altres docents puguin bifurcar i adaptar el recurs.
Bloc 8

Llista de verificació abans de portar el recurs a l'aula

Comprovacions imprescindibles de contingut i privadesa

  • ✓ Respostes i continguts pedagògics verificats personalment pel docent.
  • ✓ Zero sol·licitud de dades personals de l'alumnat (cap formulari de registre).
  • ✓ Provat en mòbils i tauletes amb disseny adaptatiu.
  • ✓ Botons grans i fàcils de prémer, contrast cromàtic que compleixi pautes WCAG.
  • ✓ Llicència clara indicada al peu de pàgina i enllaç al repositori públic.
Bloc 9

Per continuar explorant: models d'intel·ligència artificial local

Privadesa absoluta, funcionament fora de línia i recursos en català

L'execució de models en local permet gaudir de la intel·ligència artificial sense enviar cap dada a servidors aliens, amb independència de connexió a internet i garantint la sobirania tecnològica del centre educatiu.
  • Xerrada de Jordi Mas (Softcatalà): sessió divulgativa de referència per entendre el funcionament de la IA local i la importància de disposar de models en català.
  • Catàlegs de Softcatalà: comparatives de models de llenguatge (LLM) avaluats específicament en català.
  • Rebost.ai: directori comunitari obert de recursos d'intel·ligència artificial en llengua catalana.
  • Eines visuals: programes intuïtius com LM Studio o Ollama amb interfícies com Page Assist o Open WebUI per executar models d'entre 1B i 8B paràmetres en equips convencionals.
