GitHub explicat per a docents principiants

Com entendre el servei sense termes informàtics innecessaris

Penseu en GitHub com un gran magatzem públic de carpetes. Cada vegada que prepareu una activitat interactiva amb Google Antigravity, la guardeu en una carpeta de GitHub (anomenada repositori). A més de conservar totes les vostres versions de manera gratuïta, GitHub ofereix el servei GitHub Pages, que converteix automàticament aquesta carpeta en una pàgina web visible per a tothom.

El repositori (repo)

És la carpeta del vostre projecte. Per exemple: verbs-irregulars-angles. Perquè l'alumnat pugui accedir a la pàgina sense contrasenyes ni registres, el repositori ha de ser públic.

Commit i push

Fer un commit és desar una còpia de seguretat dels canvis amb una petita descripció (com ara "afegides 10 preguntes noves"). Fer un push consisteix a pujar aquesta còpia des del vostre ordinador cap al repositori de GitHub.

El token d’accés fine-grained

Quan una eina externa necessita autenticar-se a GitHub, podeu utilitzar un Fine-grained Personal Access Token. Aquesta credencial permet limitar l’accés a un repositori concret i donar només els permisos necessaris.

Abans de publicar un repositori públic

Un repositori públic no mostra només la web final. Qualsevol persona pot consultar també els fitxers que hi heu pujat.

  • No hi publiqueu dades personals de l’alumnat ni documents interns del centre.
  • No hi deseu contrasenyes, tokens d’accés ni altres credencials.
  • Comproveu que podeu redistribuir els textos, les imatges i la resta de materials inclosos.
  • Reviseu tota la carpeta del projecte abans del primer push.

Guia de credencials per a docents que entren per primer cop

Un Fine-grained Personal Access Token és una credencial específica per a eines externes que necessiten autenticar-se a GitHub. Podeu limitar-la a un sol repositori i revocar-la sense canviar la contrasenya del compte. Si utilitzeu GitHub Desktop amb l’autenticació al navegador, no cal crear cap token.

Drecera directa: podeu anar immediatament a la gestió de credencials a través d'aquest enllaç oficial: github.com/settings/personal-access-tokens.

Fine-grained token - configuració recomanada

GitHub recomana els fine-grained personal access tokens quan són compatibles amb la tasca. Per a aquest taller, creeu primer el repositori i limiteu el token a aquell repositori. Si feu servir GitHub Desktop i l’autenticació al navegador, no cal crear cap token.

1

Creeu primer el repositori

Això permet seleccionar exactament quin projecte podrà utilitzar el token.

2

Obriu Fine-grained tokens

Aneu a Settings > Developer settings > Personal access tokens > Fine-grained tokens i premeu Generate new token.

3

Limiteu l’abast

Poseu un nom descriptiu i definiu una data de caducitat. A Repository access, trieu Only select repositories i seleccioneu el repositori del recurs.

4

Doneu permís per actualitzar els fitxers

A Repository permissions, configureu Contents - Read and write. No cal donar permís de Pages si activareu GitHub Pages manualment des de la configuració del repositori.

5

Deseu-lo com una contrasenya

Copieu el token en un gestor de contrasenyes i introduïu-lo només quan l’eina us demani autenticar-vos a GitHub. No l’enganxeu en fitxers del projecte, al README ni en cap repositori.

Si un token queda exposat, revoqueu-lo i genereu-ne un de nou.

Com activar GitHub Pages en 3 clics:

1

Entreu a Settings del repositori

Obriu el repositori on heu desat la vostra activitat i feu clic a la pestanya Settings (la roda d'engranatge a la barra superior del repositori).

2

Feu clic a Pages

A la columna de l'esquerra, feu clic a la secció Pages.

3

Trieu la branca principal i premeu Save

A l'apartat Build and deployment > Branch, seleccioneu la branca main (o master) i la carpeta arrel / (root). Premeu Save.

Resultat: en un o dos minuts, GitHub us mostrarà l'adreça web pública del vostre recurs: https://el-vostre-usuari.github.io/nom-del-repositori/. Aquest enllaç és permanent i disposa de connexió segura (HTTPS).

Veieu un 404?

Comproveu aquests punts abans de canviar la configuració a l’atzar.

  1. El fitxer index.html ha de ser a la carpeta que GitHub Pages publica, habitualment l’arrel del repositori.
  2. A Settings > Pages, confirmeu que la branca i la carpeta seleccionades coincideixen amb on són els fitxers.
  3. Reviseu majúscules, minúscules i rutes relatives. Imatge.png i imatge.png no són el mateix fitxer.
  4. Després d’activar Pages o fer un push, espereu que el desplegament acabi i torneu a carregar l’adreça publicada.

Tipus de llocs web a GitHub Pages: pàgina d'usuari i pàgines de projectes

A GitHub Pages podeu publicar dos tipus d'adreces web segons l'objectiu pedagògic de cada espai:

1. La pàgina principal d'usuari (User site)

  • Nom obligatori del repositori: ha de coincidir exactament amb nomusuari.github.io.
  • Adreça web pública: https://nomusuari.github.io/ (adreça directa a l'arrel, sense subcarpetes).
  • Quantitat: només en podeu tenir una per compte.
  • Funció pedagògica: portal central o portafolis docent on presentar-vos i reunir enllaços a tots els materials que aneu publicant.

2. Les pàgines de projecte (Project sites)

  • Nom del repositori: qualsevol nom que trieu per al vostre recurs (per exemple: eines-ia-aula o quiz-ciencies).
  • Adreça web pública: https://nomusuari.github.io/nom-projecte/.
  • Quantitat: il·limitades (podeu crear tantes pàgines de projecte com activitats necessiteu durant el curs).
  • Funció pedagògica: cadascuna allotja una activitat didàctica o recurs interactiu independent, amb el seu propi codi i enllaç directe.

Com es combinen a la pràctica? Podeu crear la pàgina d'usuari com a taulell de benvinguda de la vostra matèria, i cada activitat interactiva que creeu amb Google Antigravity serà un projecte independent amb la seva pròpia adreça. Si no creeu la pàgina d'usuari, no passa res: les pàgines de projecte funcionen de manera autònoma des del primer moment.

Tres particularitats indispensables per no tenir errors:

1. El fitxer principal s'ha de dir `index.html`

Tots els servidors web necessiten saber quina és la pàgina inicial. Si l'arxiu es diu index.html (tot en minúscules), es carregarà de manera immediata en obrir l'adreça del repositori. Si l'anomeneu d'una altra manera (com inici.html o activitat.html), l'enllaç donarà un error 404 tret que l'alumnat n'escrigui el nom complet a la barra del navegador.

2. Les rutes han de ser relatives

Quan enllaceu imatges o fitxers desats a la vostra carpeta, no poseu una barra a l'inici. Feu servir rutes relatives com ara styles.css o imatges/mapa.png, en comptes de /styles.css. D'aquesta manera funcionarà correctament dins del subdomini de GitHub Pages (veure videotutorial de rutes a YouTube ↗).

3. El repositori ha de ser públic

Per activar GitHub Pages de manera gratuïta en comptes estàndard, el repositori ha d'estar configurat com a públic. Si per error el vau crear com a privat, el podeu canviar fàcilment a públic des de Settings > Danger Zone > Change repository visibility (veure videotutorial a YouTube ↗).

GitHub Desktop i portàtils docents del PEDC

Com gestionar els repositoris sense comandes de consola i consideracions sobre els equips escolars

Per als docents que s'inicien i prefereixen una aplicació gràfica d'escriptori, GitHub Desktop és una eina gratuïta molt recomanable. Permet gestionar carpetes locals i publicar canvis a GitHub Pages amb un sol clic.

Instal·lació en els portàtils del PEDC

Tant Google Antigravity com GitHub Desktop es poden instal·lar en el portàtil docent del Pla d'Educació Digital de Catalunya (PEDC) sense necessitat de privilegis d'administració, ja que tots dos s'executen i s'instal·len dins del directori de l'usuari local. Això no obstant, cal tenir present que algunes configuracions en certs dispositius poden ser més estrictes que d'altres segons el perfil de polítiques del centre o la configuració de xarxa.

Comparació entre GitHub i GitHub Desktop

Com que tenen noms semblants, és habitual que els docents es preguntin si són el mateix servei o quina eina cal emprar a cada moment. Aquesta taula en resumeix les diferències i funcions complementàries:

Aspecte GitHub (al núvol / web) GitHub Desktop (al vostre ordinador)
On s'executa Al navegador d'internet, directament a github.com. No requereix cap instal·lació. Com a aplicació local instal·lada al vostre disc dur (en Windows o macOS).
Instal·lació al PEDC Accés web immediat des de qualsevol dispositiu amb el vostre navegador habitual. Instal·lació local senzilla a la carpeta d'usuari sense necessitat de privilegis d'administració.
Funció principal Magatzem al núvol per desar els projectes i activar la publicació a GitHub Pages. Interfície visual còmoda per sincronitzar els fitxers de la vostra carpeta local amb el repositori al núvol.
Connexió a internet Requereix connexió constant a internet per visualitzar o modificar fitxers. Podeu consultar canvis i comprovar arxius sense connexió; només cal internet en prémer Push.
Comandes de terminal No calen per a la configuració bàsica de repositoris ni per activar Pages. Substitueix completament la consola de comandes per botons gràfics (Fetch, Commit, Push).
Com es complementen On creeu el repositori públic i activeu l'enllaç web per compartir amb l'alumnat. On afegiu la carpeta del vostre recurs per pujar-hi els fitxers generats amb Antigravity en un sol clic.

Quan fer servir GitHub (web)?

  • Per crear el vostre compte docent i generar el repositori inicial.
  • Per entrar a Settings > Pages i obtenir l'adreça web pública del recurs.
  • Per generar i gestionar el vostre token d'accés personal (PAT).

Quan fer servir GitHub Desktop?

  • Per enllaçar la carpeta de treball local del vostre ordinador amb el repositori.
  • Per revisar quins fitxers ha creat o modificat Google Antigravity.
  • Per enviar les actualitzacions al núvol amb el botó Push origin en un segon.
